# FigCraft + мои доработки

Этот репозиторий хранит **только мои доработки** к [FigCraft](https://github.com/storytold/figcraft)
и автоматически собирает из них Windows-версию программы при каждом новом релизе FigCraft.

Сейчас здесь одна доработка: **OKLCH в колорпикере**. В выпадающем списке форматов
(Hex / RGB / HSL / HSB / **OKLCH** / CSS) появляется OKLCH с полями:

- **L** — светлота, %;
- **C** — хрома, % (100% = 0.4, как в CSS: `oklch(62% 64% 260)` = `oklch(62% 0.256 260)`);
- **H** — тон, °.

Значения читаются и записываются в профиле файла (sRGB или Display P3, File ▸ Color profile).
Цвет, который не помещается в охват, подгоняется по алгоритму CSS Color 4: хрома снижается,
светлота и тон сохраняются. Расчёты сверены с эталонной библиотекой coloraide
(CSS Color 4) на 6000 цветах: расхождение не больше 0.000001.

Ещё в колорпикере:

- **весь пикер работает в OKLCH**, когда выбран этот формат: вместо квадрата HSB — плоскость
  OKLCH (по горизонтали хрома 0–0.4, по вертикали светлота 100%→0, при текущем тоне) с точной
  границей охвата файла (в файле Display P3 пунктиром показана ещё граница sRGB), а вместо
  радуги — полоса тона OKLCH при текущих светлоте и хроме. Тянешь тон — светлота не «гуляет»;

- **подписи над полями** во всех форматах (R G B, H S L, H S B, L C H, A);
- **ширина подстраивается** под выбранный формат; левый край можно **тянуть мышью** шире
  (двойной клик по краю — вернуть исходную ширину).

### Связи цветовых переменных с числовыми

Цветовую переменную можно вычислять из числовых. Открой цветовую переменную в редакторе
переменных, кликни по образцу цвета, выбери формат **OKLCH** — под полями появится строка
**Linked to number variables** с выпадающими списками **L / C / H**. Выбери, например, для H
числовую переменную «Тон» — теперь при изменении «Тон» с 280 на 130 цвет пересчитается сам,
вместе со всеми слоями, где он используется (одним шагом Ctrl+Z).

- L из переменной — в процентах (0–100), C — как в CSS (0–0.4), H — в градусах.
- Если числовая переменная в той же коллекции, что и цвет, берётся значение того же режима
  (можно сделать разную светлоту для Light и Dark).
- Связь хранится строкой в описании переменной: `oklch(62% 0.19 {Тон})` — её можно писать
  и править руками. Переименуешь числовую переменную — поправь имя и в формуле.
- Если поменять сам цвет (HEX, пипетка), несвязанные каналы формулы обновятся, связанные останутся.
- В обычном FigCraft без доработки цвета просто останутся последними вычисленными.

## Как это устроено

```
overlay/      мои файлы — копируются в FigCraft по тем же путям
hooks/        точки подключения: «вставить строку после такой-то» / «заменить такой-то текст»
scripts/      apply.py — копирует overlay/ и применяет hooks/
CUSTOM_VERSION  номер версии моих доработок (увеличить на 1 после изменений)
.github/workflows/build.yml  автосборка
```

Каждый день в 07:17 GitHub проверяет, вышел ли новый релиз FigCraft. Если вышел — скачивает его,
подключает доработки, прогоняет тесты, собирает Windows-версию и публикует её в **Releases**
этого репозитория под именем вида `v0.5.2-custom.1`.

Если обновление FigCraft сломало подключение (разработчики переписали колорпикер), сборка
остановится, на почту придёт письмо от GitHub, а прошлая рабочая версия останется в Releases.
В письме/логе будет написано, какая точка подключения не нашлась (например
`0001-oklch-colour-picker.json #5 (picker: OKLCH fields)`). Тогда нужно поправить её текст-якорь
в `hooks/` — обычно это одна строка.

## Как скачать готовую программу

1. Открой вкладку **Releases** справа на главной странице репозитория.
2. Скачай `figcraft-…-windows-x64-portable.zip`.
3. Распакуй на флешку и запускай `figcraft.exe`.

## Как запустить сборку вручную

**Actions** ▸ **Build FigCraft + custom** ▸ **Run workflow**. Можно указать конкретный тег
FigCraft (например `v0.5.1`) или поставить галочку `force`, чтобы пересобрать уже вышедшую версию.

## Как добавить новую доработку

1. Новый код — отдельными файлами в `overlay/` (по тем же путям, что в FigCraft).
2. Точки подключения — новым файлом `hooks/0002-….json` (по образцу 0001).
3. Увеличить число в `CUSTOM_VERSION`.

Сборка запустится сама после сохранения изменений.
